Crowdsensed mapping after disasters | blockchain

DEIMOSBC

After a hurricane, cell towers are down and nobody can be trusted to run a central server. Volunteers' phones collect GPS traces, pass them over Wi-Fi to nearby processors, and a blockchain those processors run on site checks every trace and agrees on one map of the streets that are still passable.

Ledger

Everything runs in your browser: a JavaScript port of the reference implementation walks the volunteers, runs the Trace Management System on their phones, and runs the processors' consensus and smart contracts. Block hashes are real SHA-256; signatures are simulated (the reference implementation uses Ed25519).

How it works

Four steps from a phone in a flooded street to a map anyone can check

We designed DEIMOSBC for the first hours after a disaster: no cell network, no central authority, and some participants who make mistakes or lie. Each step below can be shown on the map above.

  1. 1 | Register

    Trust only what existed before the storm

    Data processors (command posts) and pre-verified volunteers get cryptographic keys before the disaster. They are written into the first block, so nobody has to be trusted afterwards.

    Section IV-C | Register, task assignment
  2. 2 | Collect

    Phones record where people can walk

    Each phone keeps a GPS point every 10 m walked and cuts the stream at sharp turns. Finished traces wait in a queue until the volunteer comes within Wi-Fi range of a processor.

    Trace Management System | IV-B.2
  3. 3 | Verify

    The contract checks every trace

    Processors check who sent the trace and run the smart contract. Impossible data costs the sender a deposit. Traces that overlap are chained into the map. A trace that contradicts another, such as walking through a reported flood, is discarded together with it.

    Data Summarization System | IV-A.2, IV-B.1
  4. 4 | Release

    A majority publishes, or freezes

    When nothing new arrives, a majority of processors votes to release a map version anyone can download and check. If too many traces fail, a majority freezes the chain instead.

    Broadcast, retirement | IV-C

What the reference implementation shows

Our 2021 paper presented the design. Reference implementation

The Python package implements the whole system: the permissioned blockchain, the smart contracts, the Trace Management and Data Summarization systems, the three kinds of nodes, and the hurricane simulation with honest and dishonest participants.
